# v13 Dataset Design — Verified, Deterministic, Length-Safe CoT

**Goal:** break the **0.67 ceiling** by directly attacking its two root causes,
grounded in the winner's published method (tonghuikang, **0.877**) and the
competition's hard inference limits.

**Artifact:** `data/train_deterministic_v13.jsonl` — **8,332** examples.
**Generator:** `scripts/create_v13_verified.py` · **Verifier:** `scripts/verify_v13.py`.
**Training requirement (non-negotiable):** `seq_len = 8192` (see §5).

---

## 1. Why we are stuck at 0.67

We ran the same training recipe on different data and watched the score move
*only* with data quality:

| Dataset | CoT type | Score |
|--------|----------|-------|
| v8  | generic LLM CoT (short) | **0.67** |
| v11 | generic LLM CoT (more, noisier) | 0.54 |
| v9  | generic, 44.5% cryptarithm | 0.46 |
| winner | deterministic algorithmic CoT, verified | **0.877** |

Hyperparameters (lr, rank, steps, seq_len within 2k–4k) never moved us off 0.67.
**The bottleneck is the training data, not the optimizer.** Two concrete defects
in our latest data (v12) explain almost all of the gap.

### Defect A — we trained on wrong answers
v12 was generated by mechanically converting **all** 9,500 of the winner's
reasoning traces. But the winner's solver only *verifies* **8,333** of them
(`problems.jsonl` `status == "rule_found"`). The other ~1,167 are
`hypothesis_formed` / `rule_unknown` — the solver could **not** find the correct
answer, so the trace's boxed answer is **wrong**.

> Measured on `data/train_deterministic_v12.jsonl`: **1,157 / 9,482 = 12.2%** of
> examples have a `\boxed{}` answer that does **not** match the gold answer
> (using the winner's own `compare_answer`: binary→exact, numeric→`rel_tol=1e-2`).

Training on 12% wrong answers teaches the model to be confidently wrong. Almost
all of these are **cryptarithm**, a category that is only ~8% solvable and that
already sank v9 when it was over-represented.

### Defect B — half the data was being truncated
The winner's deterministic CoT is **long by design** (coverage > conciseness):
`bit_manipulation` traces run ~6,700 tokens and `equation` ~5,800 tokens. Our
overnight grid trained at `seq_len = 3072` (and 4096):

> Measured on v12: **50.2%** of examples exceed **3072** tokens and **34.1%**
> exceed **4096** tokens.

Truncated examples are cut off mid-reasoning and **never reach
`</think>\boxed{...}`**, so the model is trained to ramble without ever
committing an answer — and the worst-hit category is `bit_manipulation`, which
the winner calls *"the main differentiator."* We were silently throwing away the
single most valuable category on every step.

## 2. The competition limits pin the design

From the official evaluation config:

```
max_lora_rank = 32      temperature = 0.0     top_p = 1.0
max_tokens    = 7680    (generation budget)
max_model_len = 8192    (prompt + completion context window)
```

Two consequences:

- **Train at `seq_len = 8192`** so the full prompt+completion fits with **no
  truncation** — this exactly matches the winner's `TOKEN_LIMIT = 8192`.
- Every training **completion must be ≤ 7680 tokens**. If a learned trace needs
  more than 7680 tokens to reach `\boxed{}`, vLLM cuts generation off at
  inference *before the answer is emitted* → guaranteed wrong. So we filter the
  data to the same budget the model will face.

`temperature = 0.0` is *why* deterministic CoT wins: scoring takes the single
most-likely token at each step, so a trace where every token is trivially
derivable (the winner's design goal) is exactly what maximizes the score. There
is no benefit to diverse or "creative" reasoning here.

## 3. v13 = three changes over v12 (nothing else)

We deliberately keep the **proven v8 wrapper** (which scored 0.67) and change
only the reasoning content + filtering, so the experiment is clean.

1. **Verification filter** — keep only `status == "rule_found"`. Removes the
   12.2% wrong-answer examples. *Verified: v13 has 0 answer mismatches vs gold.*
2. **Length safety** — keep only `completion ≤ 7680` **and** `total ≤ 8192`
   tokens (counted with the competition tokenizer). Only **1** example is
   dropped for length; the rest fit because the winner designed them to.
   *Train at `seq_len = 8192` so nothing truncates (max observed total = 7,947).*
3. **Self-consistent answers** — the final `\boxed{}` uses the answer the
   reasoning actually derives (matches the winner's `corpus.py`); for
   `rule_found` that is within tolerance of gold.

**Format (unchanged from v8):**
```json
{"messages": [
  {"role": "system",    "content": "You are a helpful assistant that solves puzzles step by step."},
  {"role": "user",      "content": "<puzzle>\nPlease put your final answer inside `\\boxed{}`. ..."},
  {"role": "assistant", "content": "<think>\n<deterministic reasoning>\n</think>\n\\boxed{<answer>}"}
]}
```
Our trainer applies the chat template to these messages with `<think>` baked into
the assistant turn — identical to the v8 run that scored 0.67. We change *what
the model reasons*, not *how it is wrapped*.

## 4. Category distribution (and why we do **not** balance)

| category | v13 n | v13 % | test % | solver accuracy |
|----------|------:|------:|-------:|----------------:|
| gravity          | 1597 | 19.2% | 16.8% | 100% |
| numeral          | 1576 | 18.9% | 16.6% | 100% |
| cipher           | 1576 | 18.9% | 16.6% | 100% |
| unit_conversion  | 1594 | 19.1% | 16.8% | 100% |
| bit_manipulation | 1363 | 16.4% | 16.9% | 85% |
| equation_numeric |  561 |  6.7% |  7.7% | 77% |
| cryptarithm      |   65 |  0.8% |  8.7% | 8%  |
| **total** | **8332** | | | |

The test is **~83.5% "easy" categories** (gravity, numeral, cipher,
unit_conversion, bit_manipulation) that the winner's solver gets ~100% right.
**Getting those to ~100% is worth ~0.83 by itself.** Equation adds ~0.06.
Cryptarithm is essentially noise (~8% solvable) and the winner *abandoned* it.

We keep the **natural verified distribution** rather than forcing 1/7 each:
- Over-representing cryptarithm is exactly what caused the **v9 → 0.46**
  regression; v13 correctly leaves it tiny (0.8%).
- The categories that are slightly over-represented here are the *easy, high-value*
  ones, which is harmless — they don't compete with each other and they're where
  the points are.

## 5. How to train v13 (read this before launching)

```bash
sbatch --job-name=nem-v13 --export=ALL,\
DATA_PATH=/home/a474r867/scratch/nemotron-eco-reasoner/data/train_deterministic_v13.jsonl,\
OUT_PATH=/home/a474r867/scratch/nemotron-eco-reasoner/outputs/v13_seq8192,\
TARGET_TOTAL=500,STEPS_PER_JOB=250,SEQ_LEN=8192,RANK=32,GRAD_ACCUM=4,LR=1e-4,TAG=v13-8192 \
hpc/nem_chained.slurm
```

- **`SEQ_LEN=8192` is mandatory.** Training v13 at 3072/4096 re-introduces Defect
  B and wastes the run. `use_gradient_checkpointing='unsloth'` is already on, so
  8192 fits in VRAM at batch size 1.
- Everything else mirrors the 0.67 recipe (rank 32, lr 1e-4, constant+warmup).

## 6. What we intentionally did **not** copy from the winner

The winner's other two ingredients require a different trainer (Tinker) and are
**not portable** to our Unsloth/QLoRA cross-entropy SFT — attempting them here
would be risk with no time to validate:

- **min-logprob objective** (maximize the *minimum* token logprob in a trace)
  instead of mean cross-entropy.
- **masked-token training** (loss only on reasoning+answer tokens via
  `corpus.py` masks) and **8,463 auxiliary augmentations** (matching / splitting
  / spelling / lstrip).

These are the natural **v14** experiments *if* v13 confirms the data-quality
hypothesis. v13 isolates the highest-confidence, highest-impact change first:
verified + length-safe deterministic CoT, trained at the competition's own
context length.
